# my-shops

This directory contains static storefront and brand pages generated by the **Startup Studio – session 5** n8n workflow.

The workflow acts as a virtual startup team. A chat-based Co-Founder gathers requirements, a Designer creates the visual system, a Copywriter creates the English page copy, and a deterministic code node renders the collected data as a single-page HTML storefront.

## How the Workflow Works

### 1. Setup

Run `Setup (run once)` in n8n once. It manually creates the `shops` data table using `Create table shops` with `createIfNotExists`.

### 2. Create or edit a shop

Open chat in the workflow canvas and start from `When chat message received`.

`Co-Founder` is the team lead:

- Asks one or two questions at a time.
- Challenges the concept once.
- Iterates with the founder for up to 10 rounds.
- Keeps every website to a one-page structure.
- Writes a PRD through Notion only after requirements are confirmed.
- Delegates visual changes to `Designer`, copy changes to `Copywriter`, and product or pricing changes through the PRD.
- Asks `Shall I publish it?` before publishing.

Co-Founder can use:

- `Create PRD`
- `Find PRD`
- `Read PRD`
- `Update PRD`
- `Designer`
- `Copywriter`
- `Publish shop`

PRD tools use the Notion account and the parent page `416f9e34…501e`. Find and Read operations include three retries.

### 3. Designer

`Designer` uses the Team model and has a maximum of eight iterations.

It creates:

- Five hexadecimal colors
- Two Google fonts
- Style settings such as radius, shape, density, and heading case
- Five to seven page sections and their variants
- Unsplash photo links

For a new shop, it reads the PRD. For a revision, it reads the saved shop and changes only the requested visual elements. It can call `Save design` once.

Available tools:

- `Read PRD`
- `Search photos`
- `Read shop`
- `Save design`

### 4. Copywriter

`Copywriter` uses the Team model and has a maximum of eight iterations.

It writes English copy using only information from the PRD. Missing facts use phrases such as `Contact us…`.

Expected copy includes:

- A slogan of eight words or fewer
- Hero copy and CTA
- Three values
- Product names, descriptions, and prices
- Story copy of no more than 60 words
- Four to six FAQs
- Contact and footer copy

Available tools:

- `Read PRD`
- `Read shop`
- `Save texts`

### 5. Storage

The workflow stores shop records in the `shops` table (`o4ZkDiVXCZI9CI2L`).

| Column | Purpose |
| --- | --- |
| `shopName` | Unique lookup name |
| `prdPageId` | Related Notion PRD page |
| `version` | Shop version |
| `design` | JSON-encoded design settings |
| `texts` | JSON-encoded page copy |

Upsert operations match the `shopName` field. The current One Bookshop record is available in this table.

### 6. Rendering

`Get shop sheets` loads the saved shop data. `Build page (Lego bricks)` is a deterministic Code node with no AI that converts the design and text data into HTML.

The Lego brick system provides:

- Seven block types
- Two or three variants per block
- Hero variants: split, full, and center
- Products variants: grid, list, and featured
- FAQ variants: accordion and columns
- Automatic block deduplication
- A mandatory products section
- Default sections when required data is missing

Before rendering, the workflow:

- Replaces illegal colors or low-contrast combinations with readable alternatives
- Requires at least 4.5:1 text contrast
- Normalizes Unsplash URLs with `w=1080&q=80`
- Safely parses design and text JSON strings
- Returns a `No shop yet` page when the requested shop cannot be found

The workflow decides between preview and publishing with `Visit or publish?`:

- Preview mode reads `shopName` from the `Site visit` webhook query.
- Publish mode reads `shopName` from the tool workflow input.
- Both paths match names case-insensitively after removing diacritical marks.

## Publishing

Publishing uses the GitHub account configured for `My GitHub repo`:

- Owner: `77Lq77`
- Repository: `my-shops`

The publish path is:

1. `GitHub: create the page` writes `<folder>/index.html`.
2. If creation fails, the error is checked by `File already exists?`.
3. When the error is a 422, SHA, or already-exists response, `GitHub: update the page` updates the file with up to three retries.
4. Success returns `https://77lq77.github.io/my-shops/<folder>/`.
5. If the create operation fails for another reason, `Answer: not published` forwards the raw GitHub error to Co-Founder and disables retries.

The One Bookshop page is published at:

- <https://77lq77.github.io/my-shops/one-bookshop/>

## Technical Notes

- Built with plain HTML, CSS, and JavaScript
- No build step or npm dependencies are required
- Page styles and scripts are kept in each store's `index.html`
- Product images and fonts are loaded from external CDNs
- If an image fails to load, a colored fallback block remains visible
- The contact form uses `mailto:` and does not submit data to a backend
- Generated HTML has no n8n runtime dependency and can be hosted independently

## Adding or Updating a Store

1. Open the Co-Founder chat and describe the new shop or revision.
2. Let Co-Founder delegate visual work to Designer and copy work to Copywriter.
3. Review the generated preview at `/webhook/site?shop=<name>`.
4. Ask Co-Founder to publish it only after confirming the page.
5. The workflow creates or updates `<folder>/index.html` in the `77Lq77/my-shops` GitHub repository.
6. Add the new store to the table above if it is not already listed.
